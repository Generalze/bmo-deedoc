## Why this differs so sharply from Sprint 3

The Sprint 3 matrix largely asked *"does an implementation exist?"*. This audit
asks the locked question: *"does the intended workflow run end-to-end, for the
intended role, with authorization, persistence and evidence?"*

Five systemic findings account for most of the movement. Each is a concrete,
path-cited defect, not a difference of opinion:

1. **The legacy national surface is still mounted.** `apps/api/src/routes/admin.ts`
   (~6,000 lines) still operates on `GeoPoliticalZone` and `AdminLevel`
   `NATIONAL`/`GEO_POLITICAL_ZONE`/`STATE`, `GET /auth/territories/states`
   returns all 37 states, and `POST /auth/register-voter` accepts any `stateId`.
   Ogun-only is a property of the new command layer, not of the platform.
   Affects 001, 003.

2. **LGA is still a live command level in the legacy layer.** `apps/api/src/scope.ts`
   ranks `LGA:1` and `POST /admin/users` creates `AdminProfile` records with
   `adminLevel: 'LGA'`. The target layer correctly excludes it; the legacy layer
   does not. Affects 003.

3. **Specialist roles could not reach their own workspace.** `VALIDATOR` and
   `PAYOUT_OFFICER` were rejected by the only page that issues an admin session,
   so the verification queue and payout queue were dead UI for the only roles the
   API permits to use them. **Fixed in this PR** (see below). Affected 008, 027,
   028, 030, 056.

4. **Member constituency ancestry is never populated on the real write path.**
   **[CLOSED in the P0 #4 branch — see `docs/MEMBER_ANCESTRY.md`. The code path
   is implemented and the request contract no longer accepts caller-supplied
   ancestry; operational completeness still waits on human review of the 56
   inferred constituency edges.]**
   `VoterProfile.senatorialDistrictId` / `federalConstituencyId` /
   `stateConstituencyId` are nullable, the public registration form collects only
   State → LGA → Ward → PU, and `apps/api/src/routes/auth.ts` stores
   `parsed.data.X || null` without deriving ancestry from the ward it already
   validated. Every member registered through the product is therefore invisible
   at three of the six dashboard levels, which band `CRITICAL` regardless of real
   strength. Affects 059–065, 077.

5. **Two disjoint reward ledgers with an ungated money-out path.**
   `RewardLedgerEntry` feeds the threshold-gated payout module, while the legacy
   `RewardLedger` feeds `POST /voter/redemptions`, which checks only
   `pointsRequested > availablePoints` and accepts a **client-supplied**
   `amountRequested` — never consulting `PayoutConfiguration.minimumPoints` or
   `pointConversionRate`. Affects 049, 051, 058.

## Corrections to previously reported status

Two claims made in earlier sprint reports did not survive this audit and are
corrected here:

- **Feature 110 (In-App Voice Calling)** was reported COMPLETE in PR #6. That was
  wrong. `apps/web/components/voice-call-panel.tsx` creates an
  `RTCPeerConnection`, adds local tracks and sets `ontrack`, but never calls
  `createOffer`, `createAnswer`, `setLocalDescription`, `setRemoteDescription`,
  or `addIceCandidate`, and never invokes the `sendElectionDayCallSignal` client
  that exists in `apps/web/lib/api.ts`. **No SDP or ICE is ever exchanged, so a
  call can never carry audio** — the UI displays "Connected" from the durable
  REST state while no media path exists. The durable lifecycle, permissions and
  history are real and tested; the media negotiation is absent. **PARTIAL.**

- **Feature 139 (Evidence Retention Policy)** is **BLOCKED**, not PARTIAL. The
  repository contains only the hard-coded string
  `ELECTION_EVIDENCE_STRONG_RETENTION_TARGET` and a `LEGAL_HOLD` enum value.
  Retention duration, legal-hold duration and destruction policy are governance
  decisions and must not be invented.

| Wards | MISSING |
| Polling Units | MISSING |
| PU geodata | MISSING |

Because `resolveOperationalTerritory` fails closed on incomplete ancestry and
`organization-tree.ts` returns 409 on the Ogun counts, **no State Constituency,
Ward or Polling Unit coordinator can be created against real data.** Every
command-hierarchy test below Federal Constituency passes only against synthetic
fixtures.

This is correct fail-closed behaviour and must not be relaxed. Missing
authoritative data is never rendered as legitimate zero-strength territory —
the dashboard reports `referenceDataIncomplete` instead.
